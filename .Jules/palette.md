## 2026-08-01 - Accessible and Non-blocking Async Confirmation Dialogs
**Learning:** Browser-native `window.confirm` blocks the main thread and offers poor visual consistency and zero screen reader customization. Replacing it with a custom dialog wrapping Radix UI `AlertDialog` primitives combined with React's `useTransition` creates a delightful, fully accessible (focus trapped, keyboard accessible) experience. Using `.catch()` and `.finally()` on the async server action promises is critical to guarantee that the deletion state (`logToDelete`) is always cleared, preventing dialog lockups if an action fails.
**Action:** When performing destructive or critical async operations, implement state-driven custom `ConfirmDialog` components wrapped inside a synchronous `startTransition` block with strict promise lifecycle handling to manage loader/disabled states and ensure proper UI feedback.
